### <a name="_qmphm5d6rvi3"></a>**Решение**

В рамках предложенного решения предлагается расширить функциональность Сервиса управления депозитами, 
созданного в предыдущем ADR, добавив в него компоненты для обеспечения доступа к ставкам для кол-центров.

- [context diagram](context_diagram.puml)
- [container diagram](container_diagram.puml)

### Логика принятия решений:

- Централизованное хранилище ставок: 
  - Основная идея решения - создание единого источника правды для ставок по депозитам, что упрощает их обновление и синхронизацию между системами.

- Два механизма доступа:
  - Для внутреннего кол-центра: через REST API, что обеспечивает почти мгновенный доступ к актуальным данным
  - Для партнерского кол-центра: через экспорт и передачу файлов, учитывая ограничение на невозможность API-интеграции
- Планировщик экспорта: 
  - Автоматизация процесса экспорта файлов по расписанию (например, раз в час) для обеспечения актуальности данных в партнерском кол-центре.

- Безопасная передача файлов: 
  - Использование SFTP протокола для безопасной передачи файлов с данными о ставках.

- Мониторинг и уведомления: 
  - Внедрение компонентов для отслеживания процесса передачи данных и оповещения о возможных сбоях.

Данное решение позволяет удовлетворить все функциональные и нефункциональные требования, сохраняя совместимость с существующей архитектурой системы.

### Альтернативы

- Прямая интеграция систем кол-центров с АБС
  - Преимущества: Исключение промежуточного слоя, прямой доступ к данным
  - Недостатки: Дополнительная нагрузка на АБС, сложности с внедрением изменений, риски безопасности
- Веб-портал для партнерского кол-центра
  - Преимущества: Доступ к актуальным данным в реальном времени, исключение необходимости импорта файлов
  - Недостатки: Требует разработки и поддержки дополнительного веб-приложения, необходимость внешнего доступа к внутренним системам банка
- Использование общей базы знаний
  - Преимущества: Единая система для всех справочных данных, не только ставок
  - Недостатки: Излишняя сложность для текущей задачи, увеличение сроков и стоимости проекта
- Email-рассылка файлов с ставками
  - Преимущества: Простота реализации, использование существующих каналов коммуникации
  - Недостатки: Меньшая надежность, проблемы с автоматизацией, риски безопасности

### Недостатки, ограничения, риски

Недостатки:

- Дополнительный уровень сложности в архитектуре за счет внедрения модулей экспорта и передачи файлов
- Потенциальная задержка в актуализации данных в партнерском кол-центре из-за периодического характера обновлений
- Необходимость поддержки дополнительных компонентов и процессов

Ограничения:

- Зависимость от возможностей системы партнерского кол-центра по импорту файлов
- Необходимость согласования формата данных с партнерским кол-центром
- Ограничения SFTP протокола (например, по размеру передаваемых файлов)
- Возможная необходимость одобрения службы безопасности для настройки SFTP-доступа к внешним системам

Риски:

- Риск несвоевременного обновления ставок в партнерском кол-центре из-за технических проблем с передачей файлов
- Риск неверной интерпретации данных в системе партнерского кол-центра
- Риск безопасности при настройке внешнего доступа к системам банка
- Сложности с отладкой и диагностикой проблем в системе партнерского кол-центра
- Риск потери синхронизации данных при сбоях в работе планировщика или модуля передачи файлов
